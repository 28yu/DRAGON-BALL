## 1. 全体の仕組み

```
閲覧者のブラウザ ──(表示・滞在時間・外部リンクのクリック)──▶ Supabase の窓口の関数 track_* ──▶ 記録の表
ダッシュボード ──(パスワード)──▶ dashboard_login ──▶ 12時間有効の鍵
ダッシュボード ──(鍵＋期間)──▶ dashboard_data ──▶ 集計結果だけを返す
```

- GitHub Pages はファイルを置いて見せるだけで記録を貯められないため、記録先に **Supabase**（データベースのサービス、無料プラン）を使う。
  - 組織：Dodeca／プロジェクト：`dragon-ball`（ref `ebyifkbzxbqstggfqqrt`、東京リージョン）。2026-10-08 作成。
  - 管理画面：https://supabase.com/dashboard/project/ebyifkbzxbqstggfqqrt
- 表は閲覧者からは**直接読めも書けもしない**（RLS を有効にし、許可を一切出していない）。閲覧者が呼べるのは決まった関数だけ。
- パスワードは Supabase の中で bcrypt（元に戻せない暗号化）で保存・照合する。サイトのファイルにはパスワードを書かない。
  - 同じ接続元で15分に5回、全体で15分に30回間違えると、しばらく受け付けない。
- `assets/js/analytics.js` の「公開用の鍵（sb_publishable_…）」は、ブラウザに置く前提の鍵で、秘密ではない。

### 記録すること・しないこと

| 記録する | 記録しない |
|---|---|
| 見たページ（トップ／商品ページの管理ID）、日時 | IPアドレス（パスワードの試行制限だけ、日付つきで暗号化した値を使う） |
| おおよその国（通信経路の国情報、なければ端末のタイムゾーン → 国） | 名前・メールなどの個人情報 |
| どこから来たか（相手サイトのドメインだけ） | 来た元のページの細かいURL |
| 端末の種類・OS・ブラウザ・言語・画面の幅 | 端末を特定できるような細かい情報 |
| 端末ごと・訪問ごとのランダムな番号（ブラウザの localStorage に保存） | |
| 滞在時間（画面が見えていた時間）・どこまで読んだか（％） | |
| 外部リンクのクリック（行き先のドメイン）・写真の拡大 | |

- 記録するのは公開サイト（`28yu.github.io`）だけ。手元の確認用サーバー・自動操作のブラウザ・ダッシュボード自体は数えない。
- ダッシュボードの「設定」→「この端末のアクセスを記録しない」で、オーナー自身の端末を除外できる（端末ごと。localStorage の `db-analytics-optout`）。
- トップページ・商品ページのフッターに、アクセス状況を記録している旨のお知らせを表示している。
- 国の判定：2026-10-08 時点で、Supabase に国情報（`cf-ipcountry`）が届くかは未確認（作業環境から Supabase に直接つながらないため）。届かない場合はタイムゾーンで判定される。どちらで判定したかは `page_views.country_source`（`edge` / `timezone`）に残る。

## 4. 作業するときの注意（Claude Code 向け）

- Supabase の変更は Supabase MCP（`execute_sql`）で行い、同じ内容を `supabase/migrations/` に新しいファイルとして残す。
  - `apply_migration` は時間切れになる。`execute_sql` で小分けに送る。
  - `delete` / `drop` を含む SQL は確認待ちになって時間切れになる（2026-10-08）。消す処理が必要なときはオーナーに相談する。
  - 2026-10-08 の最初の確認で作った `tmp_headers` 関数が残っている（中身は空・閲覧者は呼べない）。消してよいときにオーナーの承認を得て消す。
- 作業環境（クラウド）から Supabase の URL には直接つながらない（ネットワークの許可外）。画面の確認は `?demo=1` か、Playwright で Supabase への通信を模擬して行う。
- 記録はページの読み込みを妨げないように最後に読み込み、失敗しても画面には何も出さない。
- 無料プランの Supabase は、1週間ほど使われないと一時停止することがある。サイトに訪問があれば動き続ける。停止したら Supabase の管理画面で「Restore」を押す。

## 5. 将来の「誰でも使えるサイト」に向けて

- すべての記録に `site_id` を付けてあり、`sites` 表に `owner_user_id`（Supabase のアカウント機能用の欄）を用意している。
  利用者ごとのページ・コレクションができたら、`site_id`（または利用者ID）ごとに同じ集計を出せる。
- `events` 表は名前（`name`）を変えるだけで新しい操作を記録できる。例：会員登録、コレクションへの追加、検索、お気に入り。
- 改善に使える見方の例：
  - よく見られているのに「読んだ位置」が低いページ → 上の方に要点をまとめる。
  - 外部リンク（ヤフオク・メルカリなど）がよく押される → 相場の情報が求められている。
  - スマホの割合が高い → スマホでの見やすさを優先する。
  - 海外からのアクセスが増える → 英語の表示を検討する。
  - アクセスの多い曜日・時間帯 → 更新やSNSでのお知らせのタイミング。
