# 運用ルール

## データを更新するとき

1. `data/items.json` を編集する（項目の意味は [data-spec.md](data-spec.md)）。
2. 変更した商品の `history` に1行追加し、`meta.updatedAt` を更新する。
3. チェックスクリプトを実行し、エラーがないことを確認する。
   ```bash
   node tools/validate.mjs
   ```
4. ローカルで表示を確認する（README の「ローカルでの確認方法」）。
5. コミットしてプッシュする。

## 新しい収集対象を追加するとき

- `items` の末尾に1件追加します。既存の商品をコピーして書き換えるのが簡単です。
- 管理IDは同じカテゴリーの最後の番号 + 1（例：`FC-008`）。欠番は再利用しません。
- 新しい種類の商品なら、先に `categories` にカテゴリーを追加します（例：`{ "id": "sfc", "idPrefix": "SFC", ... }`）。

## 情報の調査方針

- 推測で値を埋めない。分からない項目は `value: null` / `status: "unconfirmed"`。
- 調べた情報には必ず `sources` に出典URLを付ける。
- 書店・データベース・Wiki・ブログなどの二次資料は `reference`（参考情報・要確認）。
- 現物（本の奥付、箱・カセットの表記）や公式資料で確認できたら `confirmed` に変更し、`note` に「〇年〇月〇日 現物の奥付で確認」などと書く。
- 調査した経緯は [research-log.md](research-log.md) に残す。

## 相場情報のルール

- 相場は時期によって変わるため、**必ず調査日と出典（または根拠）をセットで記録**する。
- 古い相場は削除せず、新しい記録を追加する（相場の推移を追えるようにするため）。
- 発売時の価格（`listPrice`）と、現在の中古相場（`marketPrices`）を混同しない。

## 相場の自動取得のルール

- 1日1回だけ実行する（GitHub Actions、朝6時ごろ）。取得プログラムを更新して main に送ったときにも1回実行される。サイトに負荷をかけないよう、リクエストの間は3秒以上あける。
- 実行のたびに各サイトの robots.txt を確認し、禁止されている・確認できない場合は取得しない。
- ヤフオク・駿河屋・ブックオフの利用規約では自動取得が禁止されている可能性がある。オーナーはこのリスクを理解したうえで実施を判断した（2026-10-03）。サイトから停止を求められた場合や、アクセスが拒否された場合はすぐに止める。
- メルカリは公開ページに価格が含まれず、非公開の仕組みを回避しないと取得できないため対象外とする。
- 楽天市場は公式API（2026年刷新後の新API）を使う。アプリIDとアクセスキーは GitHub の Secrets（`RAKUTEN_APP_ID` / `RAKUTEN_ACCESS_KEY`）に登録し、リポジトリには書かない。楽天側のアプリ設定では「許可されたWebサイト」に `28yu.github.io` を登録する（取得プログラムはこのサイトのURLを Referer として送る）。
- ドラゴンボールカプセルは、フィギュア1体ずつの相場を各フィギュアのページに、全種そろったセットの相場をシリーズのページに表示する（2026-10-05 オーナー指示）。
- 自動取得の値は「目安」。状態・付属品の違いは区別しないため、購入判断は個別の出品ページで確認する。

## 画像のルール

- 原則として、オーナーが撮影・作成した画像を置く。
- 例外として、**未所持の商品に限り**、オーナーが提供した参考画像（ネット上の画像など）を置いてよい（2026-10-03 オーナー判断）。その場合は `images` に `"kind": "reference"` を付け、画面に「参考画像」と表示する。購入して自分の写真を撮ったら差し替える。権利者から削除を求められた場合は、すぐに削除する。
- 置き場所は **管理IDと同じ名前のフォルダ**（例：`assets/images/items/FC-001/`）。
- ファイル名は内容を表す英語（例：`front.jpg`＝表、`back.jpg`＝裏、`cartridge.jpg`＝カセット）。一覧は [assets/images/items/README.md](../assets/images/items/README.md) を参照。
- `front.jpg` が一覧ページのサムネイルになるよう、`images` の先頭に登録する。
- スマートフォンの写真は大きいので、長辺 1200px 程度・500KB 程度までに縮小してから置く。
- 新しい収集対象を追加したら、その管理IDのフォルダも作る。
- 上記の参考画像を除き、公式画像・書籍のスキャン・他サイトの画像は保存しない。

## 所持状況のルール

- 所持状況はオーナー本人が現物を確認してから変更する。
- 初期状態はすべて「未確認（unconfirmed）」。
